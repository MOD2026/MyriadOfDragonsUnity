# Myriad of Dragons - findings package (2026-08-06)

Written to be handed to another AI. It assumes no prior context.

---

## 0. What this project is

Unity 6 (6000.5.6f1) mobile card battler, C#, **legacy uGUI** (Canvas/Image/Text/Button - NOT
TextMeshPro, NOT UI Toolkit). The entire UI is built procedurally at runtime from
`Assets/Scripts/UI/GameBootstrap.cs`; there are no scene or prefab assets. Single-player only.

A match runs **Formation -> Combat -> Resolved**:
- **Formation**: the whole squad hand is dealt at once and placed across a 3x3 board (3 lanes x 3
  slots). Front lane grants +1 Attack, Middle +1 Health, Back +2 Energy per clash. Cards can be
  recalled and re-placed freely.
- **Combat**: formation locks; lanes clash automatically every 2.2s. The player's only input is
  casting Avatar spells with Energy. Reinforcement windows open on clash 4 and 8.
- **Resolved**: an Avatar hits 0 Health, or a hard 12-clash cap is reached and the match is
  decided on remaining Health as a fraction of each side's own maximum.

Card stats are small integers (Attack/Health 1-12, cost = rarity 1-7). Rarity 5-7 cards occupy
**two** of a lane's three slots; rarity 1-4 occupy one.

45 automated EditMode tests, run headlessly. They assert **relationships**, not magnitudes (e.g.
"Avatar damage equals raw overflow times the multiplier", not "damage equals 30"), so legitimate
balance changes don't read as regressions.

## 1. Headline finding: matches were being decided on a technicality

Balance had been argued rather than measured. Simulating 4,000 matches against the shipped combat
maths showed the Avatar Health pool was roughly 3x too deep for the damage the board produces.

| Avatar HP | Ends by knockout | Ends on the 12-clash cap | Avg length |
|---|---|---|---|
| 120 | 93.8% | 6.2% | 3.4 ticks |
| 300 | 92.4% | 7.6% | 6.6 ticks |
| **400 (new)** | **89.2%** | **10.8%** | **7.9 ticks** |
| 540 | 78.5% | 21.6% | 9.2 ticks |
| 800 | 55.5% | 44.5% | 10.7 ticks |
| **1300 (old)** | **22.7%** | **77.3%** | 11.7 ticks |

Two things stand out:

1. At the old value, **77% of matches never saw an Avatar fall.** The dramatic ending was the
   minority outcome; most matches were settled by comparing percentages.
2. It got *worse with progression*. At the old max profile (1900 HP) knockouts fell to 5%, so the
   further a player advanced, the more likely their matches ended on a technicality. That is
   backwards.

**Change made:** `PlayerEmpireData` Avatar Health rescaled from 100/1300/1900 (level 1 / mid /
max) to **120/400/540**. Constants: `BaseAvatarHealth 100 -> 120`, `HealthBonusPerTier 150 -> 35`,
`MaxAvatarHealthBonus 900 -> 210`, `MaxCastleHealthBonus 900 -> 210`.

Card stats, damage multiplier, spell magnitudes and lane bonuses were **not** touched.

## 2. Balance simulation now lives in Unity

`Assets/Tests/Editor/BalanceSimulationTests.cs` runs full matches through the **real**
`LaneBattleResolver` / `BattleController` / `CardDatabase` and asserts broad ranges:

- most matches end by knockout (>55%)
- average length is between 3.5 and 11 ticks
- knockout rate does not collapse at max progression (>45%)

This matters because the earlier Python model had to duplicate the combat maths, and a duplicate
silently drifts from the game the moment either side changes. Driving the real code cannot drift.

Ranges, not exact figures: a balance change should not fail the build; a balance change that makes
matches undecidable should.

## 3. BLOCKER: the project path exceeds Windows MAX_PATH

The project was moved to:

```
G:\My Drive\card game\Game mech\MOD\Phase 1\Game mech\MyriadOfDragonsUnity
```

That root is **74 characters** (the previous root was 45). Unity's package cache contains very
deep paths; the longest now measure **266 characters** against a Windows limit of 260, and
`LongPathsEnabled` is `0` on this machine.

Symptoms observed, all from this one cause:
- `Aborting batchmode due to fatal error: Compilation Pipeline: Could not read file
  Packages/com.unity.purchasing/Runtime/WinRT/UnityEngine.Purchasing.WinRT.asmdef` - the file
  exists and is readable; the path is simply too long for the API Unity used.
- Spurious `CS0433` duplicate-assembly errors across `com.unity.burst` (Mono.Cecil vs
  Unity.Burst.Cecil) - the symptom of partially-read package metadata.
- Three package files that could not be deleted without the `\\?\` long-path prefix.

**This is not a Google Drive sync problem** - it is a path-length problem that would occur at any
location this deep. It will keep producing intermittent, misleading compile errors.

**Fix (one of):**
- Move the project to a short root, e.g. `G:\My Drive\MOD\` (16 chars). Strongly preferred - Unity
  officially recommends short project paths.
- Or set `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 1` (admin, reboot).
  Less reliable: not all of Unity's tooling honours it.

`Library/` was deleted as part of diagnosis - that is a regenerable cache, and Unity rebuilds it
on next open (a few minutes). Nothing in `Assets/`, `Packages/` or `ProjectSettings/` was touched.

**Consequence: the Unity test suite has not been run since the Avatar Health change.** The change
itself is a four-constant edit with no logic change, but it is unverified. Re-run the suite once
the path is resolved.

## 4. Open design questions, unresolved

### 4.1 Stat scale (x1 vs x10)
Card stats are 1-12. A x10 rescale has been proposed repeatedly. The usual argument - "buildings
can't grant granular bonuses at this scale" - **does not hold**, because the design also requires
that Empire buildings never grant flat stats to live cards. If buildings never buff card stats,
the problem does not arise.

The genuine argument for x10 is percentage effects (the elemental advantage), which currently only
work because the bonus is applied at *lane-sum* scale rather than per card.

If adopted, x10 is preferred to x100: same granularity per building level, but values stay 2-3
digits and need no "1.2K" abbreviation - which is a *loss* of precision, since it cannot
distinguish 1,150 from 1,249.

A rescale must be atomic across six systems: rarity stat table, spell magnitudes, synergy bonuses,
Empire health formulas, card costs, and the Avatar damage multiplier. Note the multiplier is
**scale-invariant** if stats and Avatar HP scale together, so it alone may need no change.

### 4.2 Slot weighting does not actually contain high rarity
The proposed x10 curve (rarity 4 at 48/48, rarity 7 at 96/112) is defended by "a wide board
out-damages a tall board by 36%". That measures Attack only:

- Attack per slot is **flat**: rarity 4 = 48/slot, rarity 7 = 48/slot.
- Health per slot **rises**: rarity 4 = 48/slot, rarity 7 = 56/slot (17% better).

Because overflow requires a lane to be *completely cleared*, surviving is worth more than hitting -
a lane that holds blocks everything. The curve hands the more valuable axis to high rarity. Either
set rarity 7 to 96 Health (flattening both axes) or restate the claim as a trade, not containment.

### 4.3 Not yet built
- **No save system at all.** Progress resets every launch. This blocks card levels, collection,
  and story progress. First-run tutorial gating uses `PlayerPrefs`, which is a single flag and not
  a solution.
- **No multiplayer / guild layer**, though it is the stated long-term direction.
- **Home page / main menu** - fully specified in
  `G:\My Drive\card game\Game mech\MOD\Phase 1\tutorial\Myriadtutorial Final.docx` (screen by
  screen, with slide references) but not built.

## 5. Repeated design proposals that were rejected, and why

Several of these have been proposed more than once by different sources. Rejecting them again
without the reasoning wastes time, so:

| Proposal | Why rejected |
|---|---|
| Immortal cards / "Avatar Conduit" (cards never die) | Board locks by round 3; removes Taunt's purpose, lane clearing and overflow. Match becomes arithmetic with no decisions. |
| Single unified resource for deploy + spells | Every spell then costs a deployment. The two economies are separate so neither cannibalises the other. |
| Spell catalysts (discard a card of class X to cast) | The cards worth discarding are the cards worth playing; a hand can hold no valid class, leaving the whole spell bar dead. |
| % bonuses to skill trigger chance | **There is no RNG trigger system.** Every class hook is deterministic: Knight always taunts, Strategist always draws on play, Perfect draws in Back. Proposed four separate times. |
| Card levels / fusion level caps | Needs per-card persistence; no save system exists, so levels would reset every launch. Deferred, not rejected. |
| Per-card percentage modifiers | 25% of a 3-Attack card is 0.75, rounding to +1 - exactly the flat bonus being replaced. Apply percentages at lane-sum scale instead. |
| Avatar HP in the 100,000s | Forces "1.2K" abbreviation, which loses precision, and breaks the ability to eyeball a lane clash. |

## 6. Conventions to follow when contributing

- Comments explain **why**, not what. Many existing comments record a bug that was actually hit and
  why the code guards against it. Keep that.
- Every behavioural change gets an EditMode test in `Assets/Tests/Editor/`.
- **Anything driven by `Update()` or a coroutine cannot be tested** by Unity's EditMode runner.
  Put real logic in plain, testable methods and let the MonoBehaviour supply only timing - see
  `BattleController.AdvanceCombatTick()` for the pattern. This is why the combat timer, all
  animations, and the story/tutorial overlays are unverified by the suite.
- Assert relationships, not magnitudes, so balance changes don't read as regressions.
- Run headlessly:
  `Unity.exe -batchmode -projectPath <proj> -runTests -testPlatform EditMode -testResults <x.xml> -logFile <y.log>`
  Never add `-quit` (it silently does nothing). Paths containing spaces break Unity's argument
  parser - set the working directory to the parent and pass a relative project path.
